# Changelog

## 0.5.21

#### Fixed
- CI Docker smoke test: the DoH probe query was built by a Python one-liner with
  escaped quotes. Python raised a `SyntaxError`, the query came out empty, and the
  DoH check could never pass, so the Docker job failed on every run. The query is
  now generated by a multi-line snippet that encodes the same DNS question as the
  gateway readiness probe, using its own transaction ID; an empty query fails the
  step with a clear message.
- CI Docker smoke test: `/healthz` and `/metrics` responses are captured before
  they are matched, instead of piping `curl` into `grep -q`. Under `pipefail`,
  grep's early exit can make curl fail with SIGPIPE on a healthy container.

#### Changed
- README: clarify that the CI DoH smoke query uses the same readiness DNS
  question but an independent transaction ID (the static CI query uses ID 0; the
  running gateway increments its probe ID).
- Modified files in this release: `.github/workflows/ci.yml`, `README.md`,
  `CHANGELOG.md`. No Go code, Dockerfile, MosDNS config or shell script changed.
- The version stays `0.5.21`; `VERSION` and the Dockerfile `GATEWAY_VERSION`
  default were not changed.

#### Verified
- Unchanged code: `gofmt`, `go vet` and `go test -race` pass (run with Go 1.22 in a
  scratch copy whose `go` directive was lowered; the project keeps Go 1.27).
- `check-config.sh` passes, and all 62 validator fixtures pass.
- Entrypoint supervision tests pass under POSIX `sh` and BusyBox `ash`.
- The MosDNS config keys and plugins, the trusted-first-upstream behavior, the DoH
  `max_conns` default of 2, and the TCP/TLS-only pipeline setting were checked
  against the MosDNS v4.5.3 source.
- The changed smoke-test steps were run against the real gateway binary and
  entrypoint, with a stand-in backend that answers the readiness rule.
- Not verified here: the full Docker build and the pinned MosDNS v4.5.3 binary
  (it needs Go 1.19, which this environment does not have).
